# Instruction-Decompiler

Rewrite vague requests into explicit, checkable instructions..

## When to Use

Vague requests ('make it better', 'fix the site') produce misaligned work.

## Workflow

1. Extract implicit goals: what problem does the requester actually experience?
2. Surface hidden constraints: budget, deadline, tech limits, political constraints.
3. Define done: observable end-state both parties would accept.
4. Rewrite as explicit instruction with acceptance checks; reflect back for confirmation.
5. Record deltas between asked and understood — recurring gaps reveal communication patterns worth fixing upstream.

## Pitfalls

Interrogating instead of drafting (show a strawman, let them correct). Over-specifying beyond requester interest. Treating your interpretation as theirs without the reflection step.

## Verification

Requester confirms the rewritten version matches intent; delivered work hits the acceptance checks without mid-course correction.

## Inputs

- Task context: original vague request, requester availability

## Outputs

- explicit instruction + acceptance criteria + confirmation
