# Style-Guide-Distiller

Extract a project's voice rules from existing copy samples..

## When to Use

Projects accumulate copy in inconsistent voices; new writing guesses at tone.

## Workflow

1. Collect the project's best-received existing copy (docs users praised, emails that worked).
2. Extract observable patterns: sentence length distribution, vocabulary level, person (you/we/I), verb mood, humor tolerance.
3. Note hard rules discovered: terms never used, claims never made without links.
4. Distill into rules a stranger can follow, each with an example pair (do this / not this).
5. Validate: writer unfamiliar with project produces on-voice sample using only the guide.

## Pitfalls

Distilling aspiration instead of practice ('be clear' helps nobody). Rules so long they're ignored. Voice guides that fight the platform's native conventions.

## Verification

Blind-writer test passes; guide fits one page or is organized for lookup; examples outnumber abstractions.

## Inputs

- Task context: existing copy corpus

## Outputs

- one-page voice guide with example pairs
