# Onboarding-Doc-Audit

Audit onboarding docs against a newcomer's actual first day..

## When to Use

New team members keep asking the same questions the docs 'already answer'.

## Workflow

1. Shadow an actual newcomer through their first week; log every doc lookup and its outcome (found/found-after-pain/not-found/misleading).
2. Audit against reality: does setup doc match current machine state? Version drift check on every command.
3. Find tribal knowledge: things newcomers learn by asking, not reading — promote to docs.
4. Fix findability: the answer exists but lives where nobody looks.
5. Instrument: add feedback path so future gaps self-report.

## Pitfalls

Auditing by reading (you have the context newcomers lack). Fixing content while ignoring discoverability. Docs updated once, never again — audit cadence matters more than perfection.

## Verification

Next newcomer completes first-week setup consulting support channels measurably less; their confusion log becomes next audit's input.

## Inputs

- Task context: access to a real newcomer's journey

## Outputs

- gap report + fixed docs + feedback loop installed
