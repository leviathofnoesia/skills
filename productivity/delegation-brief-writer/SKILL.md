# Delegation-Brief-Writer

Write delegation briefs with done-states and acceptance criteria..

## When to Use

Delegated work returns wrong because the brief lived in your head or was one vague sentence.

## Workflow

1. State outcome definitionally: what does DONE look like, observable?
2. Name constraints explicitly: deadline, budget, tools allowed, things NOT to touch.
3. Provide context links: why this matters, who consumes it, prior attempts.
4. Define check-in cadence: milestone-based, not surveillance-based.
5. Reserve acceptance criteria: how YOU will evaluate, shared upfront.

## Pitfalls

Micromanaging method while underspecifying outcome. Assuming shared context ('the usual format'). Delegating without authority to match responsibility. Briefs so long they obscure the actual ask.

## Verification

Deliverable passes your upfront acceptance criteria with minimal rework; delegate reports clarity, not confusion; you did NOT receive intermediate questions answering things the brief should have said.

## Inputs

- Task context: the work to delegate, delegatee's context level

## Outputs

- complete delegation brief
